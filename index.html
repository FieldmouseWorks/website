Open tools for closed systems.

Fieldmouse Works builds open-source software for ecosystems that are expensive, restrictive, difficult to leave, or designed around permanent vendor dependence. The goal is practical: you should be able to run the software, understand it, move your data, and keep operating on your own terms.

wend

Language
Python, Rust
License
MIT OR Apache-2.0
Status
early

Upgrade a 2007 server to today, one release at a time, along a path someone already proved works. wend is a map of small, reviewed fixes for the places where a plain release upgrade breaks, pinned into release-to-release routes. The machine's native package manager stays in charge.

Every route carries evidence: replays from scratch on test machines in which every health check stayed green. Routes with passing replays now cover Debian 4.0 etch to Debian 13, Ubuntu 14.04 to 26.04, and CentOS 5, 7, and 8 to AlmaLinux 10.

A static Rust client is in progress. It will fingerprint a machine, pick a route, snapshot before each hop, and roll back if a check fails, with no model and no network beyond the distribution's mirrors.

Early: CI proves each route's userland in a chroot; kernels, bootloaders, and real reboots are tested separately in maintainer-run VMs. The fix format may still change. Read the README and spec.

burrow

Language
Nix, Shell
License
MIT
Status
in daily use

NixOS modules for a machine you run by talking to Claude. The coding agent gets the whole machine with no permission prompts, because nearly everything it can do undoes itself: a ZFS snapshot before anything deletes files, and a dead man's switch that brings the old system back unless a change is confirmed within ten minutes. The few one-way doors, like wiping disks or flashing firmware, still ask.

It keeps the machine current unattended, with every update built, VM-tested, health-checked and reverted on failure, and new CVEs turned into agent jobs the same hour. An always-on operator session you talk to from your phone hands project work to per-project sessions, or to a microVM per task with allowlisted egress.

In daily use on one machine; options may still move. Read the README.

Consolebook

Language
Rust
License
AGPL-3.0-only
Status
pre-alpha, v0.3.0

Self-hosted training-record software for emergency communications centers: versioned programs, Daily Observation Reports, weekly summaries, task signoffs, and trainee histories, with agency-owned data and portable records.

Implemented workflows include assignment-scoped access, immutable finalized records, acknowledgments, amendments, retention policies and holds, verifiable record exports, trainee packets, and a complete installation export that carries everything except credentials.

Rust and Axum, SQLite, and an embedded SvelteKit interface: one executable and one data directory per installation, installed and upgraded with one command. Every upgrade that migrates the database takes a validated backup first. A small center should be able to operate its own system without a collection of external services.

Pre-alpha: usable for development and evaluation only. Use invented data, never production or personnel records. Confirmed disposition, deterministic PDFs, and restore drills on real hosts remain on the roadmap.

About the name

Fieldmouse Works is named for the small creature willing to take on something much larger than itself. That is a useful model for the work here: find the closed system, understand what it actually does, and build the open door.

Built by Peter Permenter, a systems and backend engineer focused on explicit state, reproducible behavior, recovery, portability, and software that stays operable without a permanent vendor relationship.
